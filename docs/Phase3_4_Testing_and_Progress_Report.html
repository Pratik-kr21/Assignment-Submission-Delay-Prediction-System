1. Working Prototype & System Modules

1.1 Overview of Implemented Modules

The project has achieved a fully functional, container-ready prototype consisting of the following architectural modules:

  1. Data Ingestion & Synthesis Engine (src/data/make_dataset.py):
  2. Simulates and models student interaction logs, course assignments, and submission deadlines mirroring the Open University Learning Analytics Dataset (OULAD) schema.
  3. Tracks raw CSV files via DVC (student_submission_data.csv.dvc).
  4. Preprocessing & Feature Pipeline (src/features/build_features.py):
  5. Extracts historical punctuality indicators (Relative Assignment Submission Time - RAST, past delay averages).
  6. Calculates clickstream engagement velocity (clicks_last_7_days, activity_decay_ratio).
  7. Measures cognitive overload (concurrent_deadlines_window) and assessment context.
  8. Encapsulates transformations in a reusable Scikit-Learn ColumnTransformer.
  9. Model Training & Experimentation Pipeline (src/models/train_model.py):
  10. Evaluates candidate classifiers: Logistic Regression, Random Forest, and XGBoost.
  11. Integrates automated MLflow Tracking to log hyperparameters, evaluation metrics, and model binaries.
  12. FastAPI Inference Microservice (api/main.py):
  13. Exposes asynchronous REST endpoints for single-student predictions (POST /predict), cohort screenings (POST /batch_predict), and system health checks (GET /health).
  14. Validates requests with strict Pydantic V2 schemas (api/schemas.py).
  15. Interactive Streamlit Web Dashboard (frontend/app.py):
  16. 👩‍🏫 Instructor Early-Warning Portal: Displays cohort delay heatmaps, risk tier breakdowns, and auto-generates personalized intervention emails.
  17. 🎒 Student Self-Check Portal: Allows students to input upcoming workload and receive time-management action plans.
  18. 📊 MLOps Observability Portal: Features real-time Kolmogorov-Smirnov (KS-test) data drift detection to monitor semester transitions.
  19. Container Orchestration (Dockerfile, docker-compose.yml):
  20. Provides multi-service configuration connecting FastAPI, Streamlit, and the MLflow Tracking Server.

3.2 Multi-Model Performance Benchmarking

Three candidate algorithms were evaluated on identical stratified test partitions (500 held-out student records):

Model Architecture Accuracy Precision Recall F1-Score ROC-AUC
Logistic Regression (Baseline) 86.20% 71.23% 52.00% 0.6012 0.9044
Random Forest 85.20% 72.41% 42.00% 0.5316 0.8697
XGBoost (Production Selected) 86.60% 72.60% 53.00% 0.6127 0.8813
  • Model Selection Justification:
    XGBoost achieved the highest overall Accuracy (86.60%), Precision (72.60%), and F1-Score (0.6127). In educational early-warning systems, high precision is prioritized to prevent "alert fatigue" (falsely flagging on-time students).

3.3 Visualizations & Evaluation Graphs

1. ROC Curves Comparison

* Analysis: Both XGBoost (AUC = 0.881) and Logistic Regression (AUC = 0.904) exhibit strong separability, significantly exceeding random chance across all operating thresholds.

2. Confusion Matrices

* Analysis: Across the 500 test samples (400 on-time, 100 late), XGBoost accurately isolated 53 late submitters with only 20 false alarms, outperforming Random Forest which suffered higher false negatives.

4. XGBoost Feature Importance

* Key Finding: The most influential predictors of delay are: 1. hist_late_rate & hist_avg_delay_days: Historical habits are the strongest predictors of future lateness. 2. clicks_last_7_days: Disengagement directly precedes late submissions. 3. concurrent_deadlines_window: Scheduling density increases probability of delay.

3.4 Identified Issues & Corrective Solutions Implemented

# Identified Issue / Bug Root Cause Implemented Solution
1 UntrustedTypesFoundException during MLflow model logging. MLflow 3.x utilizes strict skops security audits rejecting XGBoost C-pointer types. Configured serialization_format="pickle" with automatic fallback to mlflow.log_artifact().
2 FastAPI TestClient returned HTTP 503 during unit tests. @app.on_event("startup") was deprecated and not triggered by isolated test runners. Re-architected startup lifecycle using modern lifespan context manager and a lazy get_predictor() loader.
3 dvc add failed with bad DVC file name git-ignored. Root .gitignore had blanket wildcard /data/raw/*. Added exceptions for !*.dvc and !/data/**/.gitignore to properly version control metadata.
